# GLVQ (Learned Lattice Vector Quantization) Implementation

## Overview

GLVQ is Phase 3 of the per-block codebook quantization framework. It extends Phase 2 (EM-optimized codebook) by learning per-block lattice transformation matrices that enable efficient nearest-lattice-point quantization via Babai rounding.

**Key Innovation**: Instead of using a fixed codebook, GLVQ learns an optimal linear transformation (lattice basis) for each block, then quantizes to the nearest lattice point. This provides:
- Better exploitation of block-specific weight distributions
- Geometric efficiency through lattice structure
- Differentiable quantization via Babai rounding algorithm
- Improved reconstruction quality compared to scalar quantization

## Mathematical Foundation

### Lattice Quantization

A lattice Λ is a discrete subgroup of ℝⁿ generated by a basis matrix A ∈ ℝⁿˣⁿ:

```
Λ = {Az : z ∈ ℤⁿ}
```

For a weight block w ∈ ℝⁿ, lattice quantization finds the nearest lattice point:

```
w_quant = A · round(A⁻¹ · w)
```

where `round()` is element-wise rounding to nearest integer.

### Babai Rounding Algorithm

The Babai nearest-plane algorithm efficiently finds the nearest lattice point:

1. Solve the linear system: `z = A⁻¹ · w`
2. Round to nearest integers: `z_rounded = round(z)`
3. Reconstruct: `w_quant = A · z_rounded`

**Complexity**: O(n²) for solving the linear system (via LU decomposition or pseudo-inverse)

**Numerical Stability**: Condition number of A must be < 1000 to avoid numerical errors

### Lattice Basis Learning

For each block, we learn the transformation matrix A by minimizing reconstruction error:

```
A* = argmin_A ||w - A · round(A⁻¹ · w)||²₂
```

This is solved via gradient descent with Adam optimizer:

```python
# Pseudocode
for iteration in range(max_iters):
    z = solve(A, w)
    z_rounded = round(z)
    w_recon = A @ z_rounded
    loss = ||w - w_recon||²
    A = A - lr * ∇_A loss
```

## Implementation Details

### Class: `PerBlockGLVQ`

Located in `tensorrt_llm/quantization/per_block_codebook.py` (lines 614-880)

#### Key Methods

**`__init__(block_size=128, max_iters=100, learning_rate=0.01)`**
- `block_size`: Size of quantization blocks (default 128)
- `max_iters`: Iterations for lattice basis learning (default 100)
- `learning_rate`: Adam optimizer learning rate (default 0.01)

**`_learn_lattice_basis(block)`**
- Input: weight block of shape (block_size, block_size)
- Output: transformation matrix A of shape (block_size, block_size)
- Algorithm: Gradient descent with Adam optimizer
- Constraint: Condition number(A) < 1000 for numerical stability

**`_babai_round(block, A)`**
- Input: weight block, transformation matrix A
- Output: quantized indices z (integer tensor)
- Algorithm: Solve Az = block, round to nearest integers
- Handles shape preservation (1D ↔ 2D conversion)

**`quantize(weights, scale=None)`**
- Input: weight tensor of shape (M, N), optional per-block scale
- Output: quantized tensor, metadata dict
- Process:
  1. Divide into blocks of size (block_size, block_size)
  2. For each block:
     - Normalize by scale
     - Learn lattice basis A
     - Apply Babai rounding
     - Store A and scale in metadata
  3. Return quantized blocks and metadata

**`dequantize(quantized_weights, metadata)`**
- Input: quantized tensor, metadata dict
- Output: reconstructed weight tensor
- Process:
  1. For each block:
     - Retrieve transformation matrix A and scale
     - Reconstruct: w_recon = A @ z_rounded
     - Denormalize by scale
  2. Reassemble blocks into original shape

### Metadata Structure

```python
metadata = {
```

## Algorithm Walkthrough

### Example: Quantizing a 256×256 Weight Matrix

**Input**: weight matrix W ∈ ℝ²⁵⁶ˣ²⁵⁶

**Step 1: Block Division**
```
Divide W into 4 blocks of 128×128:
W = [W₁₁  W₁₂]
    [W₂₁  W₂₂]
```

**Step 2: Per-Block Quantization (for W₁₁)**
```
1. Compute scale: scale = max(|W₁₁|) / 6  (normalize to [-6, 6])
2. Normalize: w_norm = W₁₁ / scale
3. Learn lattice basis A via gradient descent:
   - Initialize A = I (identity matrix)
   - For 100 iterations:
     - z = solve(A, w_norm)
     - z_rounded = round(z)
     - loss = ||w_norm - A @ z_rounded||²
     - Update A via Adam
4. Apply Babai rounding:
   - z = solve(A, w_norm)
   - z_rounded = round(z)
5. Reconstruct:
   - w_quant = A @ z_rounded
   - w_quant_scaled = w_quant * scale
6. Store: (w_quant_scaled, A, scale) in metadata
```

**Step 3: Dequantization**
```
For each block:
1. Retrieve A and scale from metadata
2. Reconstruct: w_recon = A @ z_rounded
3. Denormalize: w_recon_scaled = w_recon * scale
4. Reassemble into original shape
```

## Performance Characteristics

### Compression Ratio

Typical compression ratios for GLVQ:
- **Block Size 64**: 2-4x compression
- **Block Size 128**: 4-8x compression (recommended)
- **Block Size 256**: 6-10x compression

Compression ratio depends on:
- Block size (larger blocks → higher compression)
- Weight distribution (more uniform → higher compression)
- Quantization precision (fewer bits → higher compression)

### Reconstruction Error

Typical reconstruction errors (MSE):
- **Small weights** (scaled by 0.01): MSE ≈ 0.001
- **Normal weights** (unit scale): MSE ≈ 0.1-0.2
- **Large weights** (scaled by 100): MSE ≈ 100-200

Reconstruction error scales with:
- Block size (larger blocks → lower error)
- Learning iterations (more iterations → lower error)
- Lattice basis quality (better condition number → lower error)

### Computational Cost

**Quantization Time** (per block):
- Lattice basis learning: O(block_size³) for matrix operations
- Babai rounding: O(block_size²) for solving linear system
- Total: ~100-200ms per 128×128 block on CPU

**Dequantization Time** (per block):
- Matrix multiplication: O(block_size²)
- Total: ~1-2ms per 128×128 block on CPU

**Memory Overhead**:
- Transformation matrices: block_size² floats per block
- Scales: 1 float per block
- For 256×256 matrix with 128×128 blocks: 4 × (128² + 1) ≈ 65KB overhead

## Numerical Stability

### Condition Number Monitoring

The condition number of transformation matrix A is critical:

```python
cond_A = torch.linalg.cond(A)
if cond_A > 1000:
    # Warning: numerical instability risk
    # Solution: regularize A or reduce learning rate
```

**Typical Condition Numbers**:
- Well-conditioned: cond(A) < 100
- Acceptable: cond(A) < 1000
- Problematic: cond(A) > 1000

### Handling Edge Cases

**Small Weights** (e.g., scaled by 0.01):
- Lattice basis learning may diverge
- Solution: Use smaller learning rate (0.001) and more iterations (200)

**Large Weights** (e.g., scaled by 100):
- Rounding errors may accumulate
- Solution: Use pseudo-inverse instead of direct solve for numerical stability

**Singular Matrices**:
- If A becomes singular, use pseudo-inverse: `z = torch.linalg.pinv(A) @ block`
- Adds robustness at cost of slightly higher reconstruction error

## Usage Example

```python
from tensorrt_llm.quantization.per_block_codebook import PerBlockQuantizationConfig

# Create GLVQ quantizer
config = PerBlockQuantizationConfig(method='glvq', block_size=128)
quantizer = config.create_quantizer()

# Quantize weights
weights = torch.randn(4096, 4096)
quantized, metadata = quantizer.quantize(weights)

# Dequantize
reconstructed = quantizer.dequantize(quantized, metadata)

# Check reconstruction error
error = torch.norm(weights - reconstructed) / torch.norm(weights)
print(f"Reconstruction error: {error:.4f}")
```
